# リリース前の確認（セルフホストで実運用に載せられる最低線）

**このファイルの目的**: 誰かがこのリポジトリをクローンし、初期設定をして立ち上げたときに、
**サービスとしてそのまま使える状態か**を確かめる。ここが全部通ってから公開する。

- 全項目に**確認の仕方**を書く。読んで判断するのではなく、実際に動かして確かめる。
- 落ちた項目は、直すか、**直さない理由と回避方法を `README` に書く**。黙って残さない。
- 判定は3つだけにする。**通った / 落ちた / この版では対象外**。

| 記号 | 意味 |
|---|---|
| ✅ | 実際に動かして通った |
| ❌ | 落ちた（直す） |
| ⏭ | この版では対象外（理由を書く） |

## A. 立ち上げ（何も知らない人が10分で動かせるか）

| # | 確認すること | 確認の仕方 | 判定 |
|---|---|---|---|
| A1 | `git clone` → `docker compose up` だけで動く | 空のディレクトリでクローンし、`.env` を作らずに起動する。`http://localhost:8787` が開く | |
| A2 | `.env.example` をコピーするだけで動く | `cp .env.example .env` → 起動。**未設定の項目があっても落ちない** | |
| A3 | Dockerを使わない起動も動く | `npm ci && npm start`。Node 22以上で動く。ビルド工程が要らない | |
| A4 | 初回のマイグレーションが自動で走る | 空のデータディレクトリで起動し、ログに `[db] applied` が出る。テーブルができている | |
| A5 | 2回目の起動でマイグレーションが二重に走らない | もう一度起動し、`applied` が出ないことを見る | |
| A6 | 最初に登録した人が管理者になる | 登録して `GET /api/me` の `isAdmin` が true | |
| A7 | 2人目以降は管理者にならない | 2人目を登録して `isAdmin` が false | |
| A8 | `AUTH_OPEN_SIGNUP=false` で登録を止められる | 設定して再起動し、2人目の登録が拒否される。**最初の1人は作れる** | |
| A9 | ポート・データ置き場を環境変数で変えられる | `PORT` と `DATA_DIR` を変えて起動する | |
| A10 | 起動に失敗したとき、原因が分かるメッセージが出る | DBのURLを壊して起動し、何が悪いか読めるか見る | |
